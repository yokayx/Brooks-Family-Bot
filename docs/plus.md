# Сборы (/плюсы)

Порт логики KillaBot → BrooksBot. Ког `bot/cogs/plus.py`.

## Кто что может

| Действие | Кто |
|----------|-----|
| `/плюсы` — создать сбор | **Head VZP**, плюс Owner / AFK Owner / Dep. Owner / руководство вне состава |
| ➕ Плюс / ➖ Минус | Любая семейная роль из состава **или** руководство |

Тип сбора задаётся в команде и даёт тег при создании (повторно при edit не пингует):

| Тип | Роль |
|-----|------|
| Общий | `1552378409211142174` |
| VZP | `1551727236812640359` |

## Как работает

1. Head VZP / руководство: `/плюсы тип: Общий|VZP причина: … время: 20:00` и опционально `нужен_статик`. Без флага статик не спрашивается.
2. Время — `ЧЧ:ММ` по Москве. Если уже прошло сегодня — ставится **завтра**.
3. Бот шлёт эмбед в **этот же канал** с кнопками. `message_id` пишется в SQLite (`plus_events`), кнопки с `custom_id` живут после рестарта (`add_view` в `cog_load`).
4. **Плюс**
   - не семья → отказ;
   - сбор закрыт/нет → отказ;
   - `нужен_статик` → модалка «Статик», потом запись;
   - иначе сразу в список.
   Повторный плюс **обновляет** запись (тот же человек, новый статик).
5. **Минус** убирает себя из JSON участников.
6. После плюса/минуса сообщение **редактируется**: список заново.
7. Строка: `{n}. {ИмяИзНика} Brooks | {статик|—}`. Имя — первые `[]` латиницей, как в составе.

Закрытия сбора в этой версии нет (`is_active` всегда true после создания). Кнопки на старых сообщениях продолжают работать, пока запись в БД активна.
